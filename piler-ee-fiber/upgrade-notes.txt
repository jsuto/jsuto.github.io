# The upgrade notes of the piler-ee releases, the newest first.
# From https://docs.mailpiler.com/piler-ee-fiber/changelog/, read by piler-upgrade.sh.

## 2.3.2 - 2026-11-11
Upgrade step: piler needs Manticore 25.0.0 or newer, 29.9.0 is recommended: check the version and upgrade Manticore before piler, see Manticore 25.0.0 or newer (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#manticore-2500-or-newer-232). piler-ui doesn't start with an older Manticore.

## 2.3.1 - 2026-11-07
Upgrade step: run the migrations, see Run the migrations (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#run-the-migrations). 033 resets the date formats left over from 1.8.x, see Date formats (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#date-formats-231).

## 2.3.0 - 2026-11-04
Upgrade step: the index needs the new `participants` column, otherwise piler, piler-ui, pilerimport and reindex refuse to start. Docker deployments get it automatically; on a native install run the script once after the package upgrade, see Add the participants column (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#add-the-participants-column-230). With S3 storage, also see S3 storage settings (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#s3-storage-settings-230): s3uploader reads `/var/piler/.env` instead of `/var/piler/.env-s3`. Run the migrations too, the Docker images don't: piler-upgrade.sh runs those of the new version (piler-examples of 2026-11-02 or later, `git pull` it first), on a native install run them by hand. Among others, 029 removes secrets from the stored sessions and 030 adds the table of the health page's backups, see Run the migrations (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#run-the-migrations).
Upgrade notes: the quota user count is now the active users (email in the last 90 days), so it drops for tenants with former employees: check the user quotas. On a multi-node deployment upgrade the workers before the master; with several masters set `LEADER_ELECTION_ENABLED=true`. A `/metrics` scrape through a reverse proxy needs the proxy in `TRUSTED_PROXIES`. The Docker examples keep the error directory in a `piler_error` volume, create it before the upgrade. Set `JWT_SECRET` (the same on every node) if it isn't set, or replace a value copied from an example. See JWT secret (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#jwt-secret-230), Quotas (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#quotas-230), Metrics through a reverse proxy (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#metrics-through-a-reverse-proxy-230) and Docker: the error directory volume (https://docs.mailpiler.com/piler-ee-fiber/upgrade/#docker-the-error-directory-volume-230).
